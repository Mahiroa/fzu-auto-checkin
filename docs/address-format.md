# 上报地点文案（actualLocation）的格式

> 对应字段：`checkin.actual_location`（单点）/ `checkin.locations[].actual_location`（位置池）。
> 实现：`server/internal/model/address.go`（Go）、`src/checkin.py`（Python）、`server/web/static/map-picker.js`（前端）。
> 三方一致由 `scripts/check-address-parity.mjs` + 两侧单测钉住（见 §5）。

## 1. 格式：校区 + 详细地址 + 靠近 POI

三段、一句、半角空格分隔，照学校 H5 长出来的样子写：

```
旗山校区 福建省福州市闽侯县学府南路辅路28号靠近福州大学旗山校区生活区X号楼
└校区标记┘ └── 省 / 市 / 县 + 道路门牌 ──┘└── 靠近 + POI 全称 ──┘
```

- **段一**：`旗山校区`。学校侧按校区归档，这五个字不能省，后面跟**恰好一个**半角空格。
- **正文**：`省 → 市 → 区/县 → 道路 + 门牌`。门牌级地址，越具体越好。
- **`靠近` + POI 全称**：`靠近` 与前面的门牌**紧挨着**（`…28号靠近…`，不加空格），后面接 POI 的完整名字（校区 + 楼栋），一直写到楼栋为止。
- 整串**不含换行**（接口不收带换行的值）。

`靠近` 不是冗余：正文那半段负责"在哪条路几号"，POI 那半段负责"哪一栋楼"。学校侧历史记录、App 自己拼出来的，都是这个样子，照写最不容易被当成随手编的。

## 2. 照格式填成你自己的地址

把校区门牌写进正文、把你住的楼栋写进 `靠近` 那段即可：

```yaml
checkin:
  actual_location: "旗山校区 福建省福州市闽侯县乌龙江北大道2号靠近福州大学旗山校区生活区X号楼"
```

门牌来源：高德地点「福州大学(旗山校区)」地址标为 `福州市闽侯县上街镇乌龙江北大道2号`（[amap.com/place/B024F05T6I](https://amap.com/place/B024F05T6I)），百度百科「福州大学旗山校区」同址（[baike](https://baike.baidu.com/item/%E7%A6%8F%E5%B7%9E%E5%A4%A7%E5%AD%A6%E6%97%97%E5%B1%B1%E6%A0%A1%E5%8C%BA/9232694)）；校区邮编 350108，生活区各苑（至诚苑 / 明德苑 / 博学苑 等）都是学生公寓，楼栋名按学校给的名字写。

> 本文件与仓库里的示例一律用 `生活区X号楼` 占位：宿舍楼属于个人信息，只该待在你本机那份 `config.yaml`（`.gitignore` 第 2 行，不入库）里，不进文档。

位置池里其它点照同一格式写，换楼栋只换 `靠近` 后面那段：

```yaml
checkin:
  locations:
    - longitude: "119.20463"
      latitude: "26.04920"
      actual_location: "旗山校区 福建省福州市闽侯县乌龙江北大道2号靠近福州大学旗山校区生活区X号楼"
      weight: 3
    - longitude: "119.20510"
      latitude: "26.04880"
      actual_location: "旗山校区 福建省福州市闽侯县乌龙江北大道2号靠近福州大学旗山校区教学楼"
```

## 3. 一条常见的坏数据：同一处说了两遍

```
旗山校区 福建省福州市闽侯县上街镇福州大学旗山校区生活区X号楼靠近福州大学旗山校区生活区X号楼
```

问题不在「靠近」，而在**前半段已经写到楼栋**了：高德 `regeo` 的 `formatted_address` 返回的就是"…生活区X号楼"，前端又按「靠近 POI」把同一栋楼追加了一遍。于是 `靠近` 后面跟的是前半段已经说过的内容——这时它才是冗余，应该并成一句：

```
旗山校区 福建省福州市闽侯县上街镇福州大学旗山校区生活区X号楼
```

判据（R3）只看三种情况，可预测、不猜：

| 情况 | 处理 | 例子 |
|---|---|---|
| POI 已出现在正文里（同一处说两遍） | 丢掉 `靠近X` | `…生活区X号楼靠近福州大学旗山校区生活区X号楼` → `…生活区X号楼` |
| 正文结尾与 POI 开头有 ≥4 字重叠 | 在重叠处拼接，不留 `靠近` | `…闽侯县学府南路靠近学府南路辅路28号` → `…闽侯县学府南路辅路28号` |
| 其余 | **原样保留 `靠近X`**（这是规范形态） | `…乌龙江北大道2号靠近福州大学旗山校区生活区X号楼` 一字不动 |

## 4. 规则（四步，幂等）

| 规则 | 做什么 | 例子（输入 → 输出） |
|---|---|---|
| R1 空白折叠 | 零宽字符当空格；所有空白（全角空格、换行、制表）折成一个半角空格 | `旗山校区\u3000福建省…\n…公寓` → `旗山校区 福建省… …公寓` |
| R2 校区标记 | 以 `旗山校区` 开头 → 后接恰好一个空格；没有标记但以 `福建省 / 福州市 / 闽侯县` 开头 → 补标记 | `旗山校区生活区X号楼` → `旗山校区 生活区X号楼`；`福建省福州市…` → `旗山校区 福建省福州市…` |
| R3 靠近重组 | 见 §3 的三种情况：重复才删/拼接，否则保留 | `…2号靠近…学生公寓` 原样保留 |
| R4 相邻重复折叠 | 任何 ≥3 字的相邻完全重复（`XX`）只留一段 | `…闽侯县闽侯县上街镇…` → `…闽侯县上街镇…` |

四条规则**幂等**：已经规范的文案再过一遍逐字不变（配置保存、签到解析、前端回显三处都会调用，不幂等就会来回抖）。

**不做的事**（有意为之）：

- **不替你补 `靠近` 或 POI**。手写时漏了 `靠近` 段，也不会被猜着加上——猜错了比缺一段更糟。照 §1 的格式写全即可。
- **不自动编门牌**。逆地理编码在校园内部常常只到楼栋；`乌龙江北大道2号` 这类门牌要手写（§2 已给出来源）。
- **不改用户自己的写法**。既没有 `旗山校区` 标记、也不以省市区开头的文案（如 `福州大学旗山校区生活区X号楼`）原样保留；判断只看这三个行政区划**全称**前缀，所以 `福州大学…` 不会被误判成 `福州市…`。
- **不截断**。长度超限由学校接口自己报错，脚本静默砍字只会让人找不到地址为什么少了一截。

## 5. 三端实现与一致性校验

| 入口 | 函数 | 何时跑 |
|---|---|---|
| 服务端配置 | `model.NormalizeActualLocation` ← `config.Normalize` | `PUT /api/v1/config`、导入 YAML、启动加载 |
| 服务端签到 | `fzu.actualText` → `model.NormalizeActualLocation` | 每次 `DoCheckin` 解析位置时（池项没写文案还负责回退外层） |
| Python 直跑 | `src.checkin._normalize_actual_location` | `main.py` 解析 `checkin` 段时 |
| 地图选点 | `normalizePlace` / `composePlace` | 自动取地名、用户手改后点「用这个点」 |

校验（任何一端改了规则，这三条里必有一条先炸）：

```bash
cd server && go test ./internal/model/ ./internal/fzu/ ./internal/config/
python -m pytest tests -q
node scripts/check-address-parity.mjs     # 同一张表跑 JS/Py/Go 的期望值
```

换校区（`泉港校区` 等）只需改常量 `ActualLocationCampus` / `CAMPUS_PREFIX` / `CAMPUS_TAG` 三处；换楼栋只改配置里 `靠近` 后面那段。
